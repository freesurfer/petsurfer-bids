
This folder has scripts will analyze the Cox2 data (individual and group)
from from https://openneuro.org/datasets/ds004869/versions/1.4.0 using
petsurfer-bids (see also cox2-petsurfer-km-group for group
analysis). PETprep and PetFit have already been run on this data so it is
ready for PETsurfer.

These scripts serve several purposes:
1. Stress test of petsurfer-bids by performing a wide range of analyses
2. Provides examples on how to run petsurfer-bids

To set up to run this, first create a space for the data, eg,
mkdir -p /place/for/cox2

Download it, eg, 
aws s3 sync --no-sign-request s3://openneuro.org/ds004869 /place/for/cox2/bids
Note that the data is going into the bids folder under /place/for/cox2

Note: there is an error in the 1.4 and previous versions in that the retest
session of subject sub-27 has the tracer name misspelt in the json file. To
fix, edit bids/sub-27/ses-retest/pet/sub-27_ses-retest_pet.json to change
"Mc1" to "MC1".  Make sure that there is not a backup of the json file in
the bids folder as bids will find it and generate an error. This can happen
with emacs in that it creates a .~sub-27_ses-retest_pet.json backup file.
You will not be able to see this file but bids can.

Create an environment variable
export COX2DIR=/place/for/cox2

Copy cox2.age-sex.fsgd into $COX2DIR (needed for group only)

Then run the individual
cox2-petsurfer-km --s sub-01

This will put the data into bids/derivatives/petsurfer-tut. All kinetic
models will be run, including patlak, logan, ma1, mrtm1, mrtm2, and
suvr. Note that patlak is not appropriate for this data, but we run it
anyway to assure that it actually runs. This will run the indvidual analysis
in the MNI152 volume, fsaverage space (lh and rh hemispheres), and in ROIs.
The parameters are set so that the Logan method should replicate Figure 7B
pretty closely from Yan 2025. 

Run the command above for all subjects.

To run the group analysis, run
cox2-petsurfer-km-group --all

This will run group analysis with three designs (osgm, sex-age, and paired);
the outputs will be in group/kmmethod.design. There will also be
work/group.kmmethod.design folder with useful outputs that do not get
transferred into bids output.

The scripts are set up to save the work folder. This allows easier debugging
and is necessary for some aspects of group analysis (as mentioned above).
